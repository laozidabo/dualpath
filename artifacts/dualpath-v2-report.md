## 已完成的改动

新增独立的 VerifiedDualPath / dualpath verify 模式，原有 DualPath / run 行为保留。

| 环节 | 行为 |
| --- | --- |
| 生成 | 初稿和反例发现并行；发现线路看不到初稿 |
| 反例 | 具体输入、预期输出或异常、题目原文依据；不再用无校准概率替代证据 |
| 题意复核 | 独立调用检查输入范围和预期；拒绝或有歧义的案例不进入执行 |
| 执行 | Linux bubblewrap 隔离，限制时间、内存、进程、输出和网络 |
| 修正 | 观察到接纳案例失败后才修正，最多一次 |
| 发布 | 修正通过所有已接纳检查才采用；失败或退步保留初稿 |
| 故障 | 完整 JSON 解析，截断最多恢复一次；接口、复核、沙箱失败均记录状态 |
| 费用 | 请求前预留、持久化账本、并发预算保护、未知失败保留全部预留额、不自动重试网络 |

模型盲审仍可能出错，且默认使用同一个模型，错误不一定独立。通过有限检查不代表整体正确；返回值相等检查也不能覆盖所有类型或副作用要求。默认三个案例可能覆盖不足。该版本先面向普通模型生成的 Python 函数，不是通用项目执行代理或形式化证明系统。

## 验证证据

- 62 项测试通过，含实际沙箱执行；不是仅用 mock 验证调用顺序。
- 验证了有效修复和修复退步两条路径，后者确实回退初稿。
- 覆盖 JSON 截断、非有限值、字面量注入、复核拒绝、调用上限、并发预算、未知费用重启保留、HTTP 错误日志去敏。
- 沙箱测试覆盖宿主文件/环境/网络不可访问、超时、内存/输出限制、禁止子进程和假成功退出。

## 待完成的真实对照

8 道题涵盖字符串解析、解码、精确整数分配、幂等事务、通配符、版本排序、分位数、开闭区间并集。每题共享同一份初稿，对比直接回答、一轮自检、三轮自检和新版验证模式；一轮自检是三轮自检的中间结果，不重复抽样。

使用同一模型、温度、输出上限和每方法增量费用上限，交替方法执行顺序。实际费用不会强行相等，需同时报告通过率、修复数、退步数、发现率、预期错误率、截断/故障率和费用。隐藏测试和参考实现不进入生成请求。

这些题由本次实现者编写，样本量小，且没有第三方独立基准。即使跑通，也只能提供流程和失效模式的初步证据，不能据此宣布超过普通自检。

## 我的判断

这次最有价值的进展是把“猜测可能错在哪里”转化成了可复查的反例、执行观察和回退决策。还没有证据证明这样的额外调用比一轮普通自检更划算。下一步应按已冻结协议跑完，重点观察它是否发现自检遗漏的错误，以及误判的预期会不会诱导坏修复；如果收益仍小，就优先保留低成本自检，并将验证模式用于风险较高、容易写出明确断言的任务。

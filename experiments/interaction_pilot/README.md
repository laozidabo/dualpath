# 第三批：默认反例发现 vs 规则交互反例发现

状态：**已完成真实运行（2026-10-31）**：8 题 × 4 臂、56 次成功调用、0 错误、0 截断、峰值价保守记账 0.192743 元。结果与解释见 [第三批结果报告](../../reports/interaction-pilot-results.md)。本目录是独立批次，不修改 V001–V008 的题目、协议或原始记录。

## 目的与假设

第二轮实验显示，验证模式的失效点主要在「反例发现覆盖不足」：V008 的缺陷需要同时组合「相同左端点、嵌套、不同开闭状态」三条规则才会暴露，而默认发现只生成了孤立边界案例；一次普通自检反而修好了它。

本批检验的假设只有一个：**在预先冻结的新题集上，明确要求「规则交互」的反例发现（`interaction_focus`）能否比默认发现多修复缺陷、多检出预设变异，同时不引入退步，且费用可接受。** 这是一次探索性小样本试验，不作显著性、泛化或优越性结论。

## 设计

- **8 道新题（I001–I008）**：整数比例分配、语义化版本比较、通配符匹配、时长解析、稳定去重、整数令牌桶、配置解析、连续区间合并。题目强调多条规则同时起作用时的边界与优先级。
- 每题含参考实现、隐藏测试与 1–2 个单规则变异体（共 13 个）；离线校验要求参考实现通过全部隐藏测试、变异体至少被一条隐藏测试抓住（`validate.py`）。
- **4 个对照臂**，共享同一份初稿：
  - `direct`：初稿本身；
  - `self_1`：一次「反馈 → 重写」；
  - `verified_default`：验证模式，默认反例发现，最多 3 个案例；
  - `verified_interaction`：验证模式，`interaction_focus=True`，其余参数完全相同。
- 每 3 题轮换 3 个非 direct 臂的先后顺序；隐藏测试和参考实现不进入生成请求。
- 模型温度 0.2、关闭 thinking、每次最多 2048 token；单次重复。
- 预算：本批全局增量保守上限 2.0 元，单条件每题上限 0.35 元；此前实验累计保守记账 4.74333148 元，本批完成后累计仍低于原授权 10 元。
- 任一接口错误、截断或结构失败时保留已有输出、完成当前任务后停止；不重抽题、不替换题。

## 结果摘要

- 四个方法隐藏测试均 8/8：初稿全部正确，本批没有测到修复收益；
- 预设变异检出：默认发现 4/13，规则交互发现 9/13；调用次数与案例数相同（各 16 次、24 个案例），保守费用只差约 0.0035 元；
- 两臂均为 24/24 案例被参考实现认可、0 错误预期、0 退步；逐题差异与局限见 [结果报告](../../reports/interaction-pilot-results.md)。

## 离线复放

需要 Linux、bubblewrap、可用的用户命名空间和已安装的项目开发依赖，无需 API 密钥：

```bash
venv/bin/python experiments/interaction_pilot/replay_frozen.py
# 可选：把审计写入一个不存在的新文件
venv/bin/python experiments/interaction_pilot/replay_frozen.py --report /tmp/interaction-audit.json
```

复放器校验归档与冻结文件的 SHA-256，在临时目录恢复第三批源码，逐项匹配历史请求并消费记录中的模型响应，重跑隐藏测试、变异检查、费用记账与汇总。原始记录保持不变；这不是新模型效果实验。结果见 [离线审计](../../reports/interaction-replay-audit.json)。

## 历史运行与后续批次

`validate.py`、`run.py`、`analyze.py` 是第三批冻结入口。当前项目源码已演进，直接运行旧 `run.py` 会因散列变化拒绝执行，这是预期保护；不要重新运行 `validate.py` 覆盖本批冻结文件来绕过保护。

新的付费实验应另建批次目录、题库与冻结协议，使用新的输出目录，并遵守剩余授权预算。`results/` 保存逐题记录，`ledger.json` 保存请求与费用，`summary.json` 保存评分与案例审计，`analysis.json` / `analysis.md` 是离线汇总。

## 指标

- 隐藏测试通过数，以及相对 `direct` 的修复数/退步数；
- 两个验证臂的状态分布（`checks_passed`、`repaired`、`no_cases` 等）；
- 生成反例数、被接受数、参考实现是否同意被接受案例的期望值（分歧视为错误预期信号）；
- 预设变异检出数（被接受反例作为测试运行在变异体上，任一失败即检出）；
- 调用数、截断数、错误数与峰值价保守记账。

## 边界

- 题目与隐藏测试仍由本次实现者编写，不是独立第三方基准；单模型、单次采样。
- `interaction_focus` 只改发现阶段的提示词，不增加案例数量、调用次数或修正次数。
- 通过隐藏测试不等于实现正确；未检出的变异体也不证明反例发现无效。
- 本批结果只用于判断「规则交互发现是否值得继续投入」，不能外推为一般性结论。
